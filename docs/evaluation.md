# 漫剧 Agent 评测体系 v1.0

> 目的：定义"这个 Agent 合格不合格"的可量化标准，支撑客户定制交付前的验收与回归。
> 原则：**每个指标可自动采集、可复跑、有明确阈值**——客户交付场景下，评测必须能写进合同 SLO。

## 五维评测框架

### 一、生成质量（LLM 输出维度）——决定"内容能不能用"

| 指标 | 采集方式 | 合格线 |
|------|---------|--------|
| 结构合法率 | JSON Schema 校验（评测脚本自动） | 100%（重试后） |
| 字段完整率 | sceneId/dialogue/prompt 等必填字段抽查 | 100% |
| 内容合格率 | 抽样 N 条人评（剧情通顺/人设一致/台词口语化），1-5 分 | ≥3.5 分 |
| 重复率 | 剧本/分镜文本相似度（同类选题批生成对比） | <30% |

### 二、链路能力（编排维度）——决定"流程对不对"

| 指标 | 采集方式 | 合格线 |
|------|---------|--------|
| 端到端完成率 | 全流程跑批，COMPLETED/总数 | ≥95% |
| 断点续作恢复率 | 杀 agent 进程 → 恢复 → 续作成功 | 100% |
| 人审闭环正确性 | 批准/拒绝双路径，状态机与产物符合预期 | 100% |
| 子任务粒度 | 每镜头失败只重跑该镜头，不影响整剧 | 100% |
| 产物完整性 | 成片可播放（mp4 ftyp 校验）/时长符合镜头时长和 | 100% |

### 三、稳定性（故障注入维度）——决定"敢不敢交给客户"

| 指标 | 采集方式 | 合格线 |
|------|---------|--------|
| 模拟 LLM 故障 | stub 返回 5xx/超时/截断 → 回落 Mock 不中断 | 100% |
| 模拟视频源失败 | 强制镜头失败 → 重试 2 次后降级 | 100% |
| 卡死检测 | 制造无进度剧集 → StuckScanner 5 分钟内告警 | 100% |
| 服务重启 | 各服务单独重启，状态无损 | 100% |
| 幂等性 | 重复提交同 drama → 409 拒绝，不重复生成 | 100% |

### 四、性能与成本（资源维度）——决定"账算不算得过来"

| 指标 | 采集方式 | MVP 基线 | 生产目标 |
|------|---------|---------|---------|
| 单剧端到端时延 | traceId 时间线（创建→completed） | ~60s（Mock） | P95 ≤30min（60镜头） |
| 并发承载 | 同时提交 N 剧全部完成 | 10 并发待测 | 日 10 万级 |
| LLM token 消耗 | /v1/llm/stats | 0（Mock） | 单剧 ≤50k tokens |
| 成本台账 | 每子任务记录模型调用成本 | Mock 0 元 | 单分钟成片成本可配 |

### 五、交付合规（定制维度）——决定"能不能收尾款"

| 检查项 | 方式 |
|--------|------|
| 敏感信息零泄漏 | git 仓库扫描无 .env/key/token |
| 一键部署可复现 | 干净环境 docker compose up 全链路跑通 |
| 评测可复跑 | eval_suite.py 一条命令出报告 |
| 交付物清单 | 代码+文档+部署手册+评测报告+验收记录 |

## 评测执行方式

```bash
# 全量评测（5 分钟内，Mock 模式）
cd agent && python tests/eval_suite.py
# 输出：逐项 PASS/FAIL + 汇总分数 → eval-report.json
```

**版本回归门槛**：链路/稳定性两维 100% + 质量结构项 100% 才可发布；性能维允许 Trend 标注。

## 客户定制交付的流程应用

1. **售前**：按客户场景调阈值（如完成率 99% / 时延 P95 15min），写进方案
2. **开发中**：每个迭代跑 eval_suite 回归，防止定制改动破坏主链路
3. **验收**：跑全量评测出报告，双方签字
4. **上线后**：ops 看板指标（成功率/卡死/失败子任务）即生产版持续评测
